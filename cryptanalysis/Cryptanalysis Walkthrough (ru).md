# UNSIGNAL Protocol: Аналитический разбор для спецслужб

**Автор:** Julian Cassin  
**Дата:** 2026-03-11

1. Перехват
   - Получен сырой файл: без заголовков, без магических байтов, без структуры
   - Размер файла: переменный (из-за случайного префикса/суффикса)
   - Метаданные: время, источник, назначение — ведут в никуда, не могут быть соотнесены с содержанием или намерением

2. Статистический анализ (ent)
   - Энтропия: 7.99+ бит/байт (максимум)
   - Сжатие: 0% (идеальная энтропия)
   - Хи-квадрат: проходит как случайный
   - Серийная корреляция: около нуля
   - Результат: неотличим от истинного случайного шума

3. Путаница систем координат
   - Адреса заголовка: абсолютные позиции в первых 64 КБ ПЗУ
   - Адреса данных: относительно смещения ПЗУ, полученного из самих косвенных обращений H1/H2
   - Две разные системы координат в одном файле
   - Атакующий не может интерпретировать адреса данных без:
       a) Распознавания H1/H2 как особых (они выглядят как обычные данные)
       b) Декодирования H1/H2 для получения значения смещения
       c) Применения смещения для переинтерпретации всех следующих адресов
   - Вероятность правильного угадывания без ПЗУ: ноль
   - Даже с ПЗУ необходимо знать, какие адреса являются заголовком, а какие данными
   - Совпадение заголовка и данных происходит только в 1/65536 случаев случайно

4. Анализ трафика
   - Случайный префикс/суффикс скрывает истинные границы сообщения
   - H3/H4 также сами являются косвенными обращениями
   - Переменные начальные смещения ПЗУ меняют интерпретацию для каждой сессии
   - Нет фиксированных шаблонов в размерах пакетов или времени
   - Невозможно определить, содержит ли файл данные или пуст

5. Обратная разработка
   - Кодировщик получен: однострочная таблица поиска (публичная)
   - Алгоритм: тривиален, безопасность в ПЗУ (ключ)
   - Знание принципа работы не дает преимущества

6. Атаки с известным открытым текстом
   - Один и тот же текст, закодированный дважды → разные результаты
   - Несколько вариантов адресов для каждого символа (случайный выбор)
   - Нет повторяющихся шаблонов для использования

7. Восстановление ключа
   - Полный перебор: ITS, невозможно по определению
   - Побочные каналы: простой поиск, нет сложной математики для утечки
   - ПЗУ должно быть получено физическими или юридическими методами

8. Проблема верификации
   - Любое ПЗУ декодирует что-то
   - Неправильное ПЗУ → мусор (но мусор, который выглядит реально)
   - Нет контрольных сумм, нет MAC, нет индикатора успеха
   - Невозможно проверить, какое декодирование "правильное"

9. Комбинаторный масштаб (пример с "Унесенными ветром")
   - Кодирование одного романа: >10^5,500,000 возможных представлений
   - 5 неповторяющихся адресов: 1 триллион комбинаций
   - Отслеживание до исчерпания памяти: невозможно
   - Никогда не бывает коллизий

10. Идеальная отрицаемость
    - Любое декодирование внутренне непротиворечиво
    - Любой результат можно отбросить как случайное совпадение
    - "Правильное" декодирование не определено без внешнего контекста

11. Поведение при сжатии
    - Закодированные файлы ZOSCII/UNSIGNAL не сжимаются (~0% соотношение)
    - Выходные данные уже близки к максимальной энтропии
    - Для уменьшения размера: сначала сжать входные данные, затем кодировать
    - Закодированный результат остается несжимаемым независимо от входных данных

12. Аутентификация и обнаружение подделок внутри
    - MAC, если требуется: поместите ВНУТРЬ закодированной полезной нагрузки
    - Контрольные суммы, подписи, данные верификации: все идет В сообщение
    - Применяются те же правила кодирования — они становятся неотличимы от случайного шума
    - Атакующий не может отличить данные аутентификации от содержания сообщения
    - Внешние маркеры валидации отсутствуют

13. Заключение
    - Статистические инструменты возвращают: случайный шум, ничего здесь нет
    - Анализ трафика побежден сокрытием границ
    - Восстановление ключа требует ПЗУ, а не математики
    - Верификация невозможна даже с кандидатом ПЗУ
    - Аутентификация скрыта внутри полезной нагрузки, неотличима от сообщения
    - Сжатие возможно только перед кодированием, а не после
    - Система достигает эпистемической замкнутости: атакующий не может знать, выиграл ли он
